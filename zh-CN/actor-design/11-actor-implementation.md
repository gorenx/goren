## 1. 统一实现约定

Agent 是业务身份，AgentLoop 是对应执行 owner，不再另建重叠的 AgentActor。以下业务 Actor 均以 Grain 实现，
依据是稳定逻辑身份及独立状态；普通 Actor 仅用于 PubSub 通知桥接与 GoAkt 自带 TopicActor。

每个 Grain 用具名 struct 保存自身状态，以方法处理各类消息。构造/激活只建立消息处理所需状态，
不因旧身份被访问而自动取得业务执行权。初始化必须通过所属创建事务；重新激活恢复请求策略并重新验证授权。

统一区分两类版本：实例代次表示一次实际激活，用于拒绝旧实例消息；配置版本表示有效配置/定义变化。
稳定 Grain 身份不随这两种版本变化。业务 operation ID 表示一次可查询、可重试确认的操作，不替代框架请求关联。

每个有资源的 Actor 均处理初始化、查询状态、关闭请求。对外关闭只返回“关闭中、关闭失败、关闭完成”；
停止接纳、排空和资源释放是内部阶段。业务流程见[07](./07-lifecycle-implementation.md)。
本文请求名称是语义描述，不提前发明一套英文 wire 名称。对外既有字段、工具名和错误码保持兼容。

系统运行能力直接由 GoAkt 提供；不新增 Goren Runtime 或技术路由表。
业务 Registry 管业务目录及资格，调用方通过框架逻辑身份请求目标。局部任务适配见[10](./10-runtime-and-initialization.md)。

## 2. Agent Registry 与 AgentLoop

### Agent Registry

- 身份与创建：进程内固定目录身份，由服务器启动；关闭在所有 Agent/Session 事务结束之后。
- 状态：按 SessionID 保存创建事务、当前实例代次、接纳状态、等待消息、关闭进度和父子关系。
- 请求：查找/创建 Agent、提交消息、创建 subagent、关闭 Agent、查询创建/关闭结果。
- 实现：不存在时原子预留 ID 并创建未就绪 AgentLoop；将后续同 ID 创建合并到原事务。
  AgentLoop 报告初始化完成后才转交等待用户消息。Session 创建仅由 AgentLoop 发起，Registry 不重复发起。
- 失败/关闭：创建失败追踪清理；关闭失败保留 ID 占用并重试原事务。父子关闭先完成子 Agent，
  再完成父 Agent；父 Agent 正在执行的任务仍需要子 Agent 时，先排空该任务。

### AgentLoop

- 身份与创建：按 AgentID = SessionID，由 Agent Registry 创建；它本身就是执行 Grain。
- 状态：初始化结果、已应用配置及版本、业务 FIFO、当前 Turn/Step、模型请求、工具调用及 Session 提交关联。
- 请求：初始化、用户消息、当前交互回答、取消、工具更新、关闭、查询状态。
- 实现：创建后经 Runtime 获取组件配置，再请求必要组件初始化；全部成功后报告可接纳业务。
  用户消息与工具更新按接纳顺序排队；回答与取消推进当前执行，不被当成新的普通用户消息。
  模型网络请求由受管理 task 执行，增量消息与最终结果都带 operation 身份。
- 失败/关闭：不自动重放未知工具副作用；收齐提交结果、完成 flush 和依赖释放后停止自身，
  再由 Agent Registry 协调 Session 关闭。未完整结束的业务消息不得被报告为成功完成。

## 3. Session Registry 与 SessionActor

### Session Registry

- 身份与创建：服务器启动的固定目录 Grain。
- 状态：业务 SessionID、活动实例代次、绑定关系、创建/恢复与关闭事务、目录元数据版本。
- 请求：创建/恢复并绑定、查目录、关闭 Session、查询事务结果。
- 实现：从 SessionActor 获取权威元数据更新目录；历史列表查询不激活全部 Session。
  返回绑定结果及业务 ID，由框架逻辑身份寻址，不另行登记技术地址。
- 失败/关闭：只有 Agent Registry 确认 AgentLoop 已停止，才关闭对应 Session；存储失败保留占用和历史。

### SessionActor

- 身份与创建：按 SessionID，由 Session Registry 创建/恢复。初始化读取并校验所选存储的日志状态。
- 状态：已提交事件、日志序号、FIFO 写入队列、提交操作结果、已持久化序号与活动 I/O。
- 请求：读取快照、追加事件、持久化到指定序号、提交压缩结果、查询提交结果、关闭。
- 实现：自己决定事件及提交边界，adapter 仅执行 I/O。写入/持久化串行，完成消息回到 Actor 后推进序号。
  压缩提交验证来源 Session 版本，不能覆盖提交后新增的内容；冲突明确回复，不静默截断。
- 失败/关闭：已提交事实保留；flush 失败不推进已持久化序号；重试关联原操作，不重复追加。
  关闭收齐写入和 flush 后释放存储资源。生产 commit 时点沿现有 Session 契约，不照搬文件实验。

## 4. Tools Registry、Tool Runtime 与 ToolActor

### Tools Registry

- 身份与创建：服务器启动的共享目录 Grain。
- 状态：各 Agent 有效工具集合、配置版本、更新批次、候选定义、每个 ToolActor 的实例代次与注册状态。
- 请求：开始更新批次、候选自注册、发布完整集合、查询批次、撤销注册、查询配置/目录。
- 实现：只有批次完整且期望版本匹配才在一次消息处理中替换有效目录；通知在发布后发送。
  工具定义向 Tools Registry 登记，框架逻辑身份不另建注册服务。
- 失败/关闭：发布前失败保留旧目录；重复批次返回原结果；撤销必须匹配实例和定义版本，不能删新配置。
  所有 Tool Runtime 完成撤销后关闭，不接管具体工具资源。

### Tool Runtime

- 身份与创建：按 AgentID，由 AgentLoop 初始化流程通过 Tools 组件创建。
- 状态：本 Agent 有效工具版本、工具逻辑目标、活动调用、执行预算、策略阶段、更新及资源释放进度。
- 请求：获取工具配置、初始化工具、执行、取消、更新集合、查询操作、关闭。
- 实现：公共 pre/post-policy、调度与结果校验归这里；经 Runtime 定位 ToolActor，不经 Tools Registry 转发执行。
  更新只有进入 AgentLoop 业务屏障后才能开始；屏障内准备、发布、切换并释放旧实现资源。
- 失败/关闭：真实调用退出并结算后释放预算；发布结果未知先查批次；旧实现释放失败不解除屏障。
  AgentLoop 排空后，逐个关闭工具，再关闭自身。

### ToolActor

- 身份与创建：按 AgentID + ToolName，新增工具时创建；替换配置/实现不创建第二个同身份 Grain。
- 状态：当前工具实现资源、候选实现资源、配置版本、活动 operation、取消句柄、延迟回复和初始化事务。
- 请求：初始化、准备候选实现、自注册、切换实现、清理候选/旧实现、执行、取消、查询结果、关闭。
- 实现：候选只允许准备与校验，不能执行用户调用。切换后旧资源仅待释放，不保留旧版本可执行入口。
  普通工具 I/O 由独立 task 完成，结果回 mailbox 后结算并回复 Tool Runtime。
- 失败/关闭：无授权的重新激活不打开文件、不连接远端；操作取消只影响原 operation。
  删除工具才撤销目录并停止 ToolActor；普通替换仅释放旧实现资源。详细事务见[08](./08-tools-implementation.md)。

## 5. Prompt Registry 与 Prompt Runtime

### Prompt Registry

- 身份与创建：服务器启动的共享定义目录 Grain。
- 状态：定义、顺序、适用范围及版本。
- 请求：解析配置、注册/更新/撤销定义、获取指定版本快照；发布变化通知。
- 实现：仅发布完整有效定义集，校验错误拒绝变更；不组装某次模型请求的 Prompt。
- 失败/关闭：消费者失败不回滚已发布定义；所有消费者解除订阅后关闭。

### Prompt Runtime

- 身份与创建：按 AgentID，由 AgentLoop 经 Prompt 组件初始化。
- 状态：本 Agent 配置、应用的定义版本、当前组装及取消记录。
- 请求：解析/获取配置、初始化、准备版本、组装、取消、关闭。
- 实现：以 AgentLoop 指定的 Session、Tools 和 Prompt 版本组装，纯模板用普通函数；耗时来源经 task/组件请求。
  一次模型请求内不混入最新定义。定义更新不改变已发模型请求。
- 失败/关闭：整体失败明确返回，收齐取消任务后释放。是否将所有定义更新加入 AgentLoop FIFO 仍需单独确定，
  本版不扩大已确认的工具更新规则。

## 6. CredentialsActor 与 ModelConfigActor

### CredentialsActor

- 实现：`credentials/actor.Grain` 是简单 get/set Grain；纯 Go Manager 拥有凭据规则，LiveStore 仅存储。
- 状态：Grain 只持有 Manager，不维护业务队列、任务代次、关闭状态、缓存或订阅。
- 请求：Initialize、Resolve、Describe、Set、Unset；业务错误保留 error，凭据名使用 string。
- 调度/生命周期：单次消息内完成操作，串行顺序和停用交给框架；不用 PipeToSelf 或额外执行 Grain。
- 安全边界：只有实际需要 secret 的 provider 操作取得值，Agent 配置、Session、普通事件和日志不包含秘密。
- 具体接口、过渡装配、取消边界及验证见[Credentials 模块设计](./15-credentials-module.md)。

### ModelConfigActor

- 身份与创建：服务器级模型配置组件，由 llm 能力提供；它不是第二个模型执行循环。
- 状态：模型/provider 定义、默认选择规则、Agent 覆盖解析、配置版本及更新状态。当前实现与尚未切换的路径见[ModelConfig 模块设计](./16-model-config-module.md)。
- 请求：解析本 Agent 模型配置、读取指定版本、更新定义、关闭。
- 实现：返回模型参数和凭据引用，不返回 SDK 实例。实际模型 I/O 仍由 AgentLoop 拥有的请求 task 与 llm adapter 完成。
- 失败/关闭：无效模型/配置明确失败，不静默换 provider；更新不修改已发请求的模型快照。

## 7. CompactionActor、QueryActor 与 ProjectionActor

### CompactionActor

- 身份与创建：按 SessionID，首次需要压缩时由 AgentLoop 初始化流程或运行请求启用；关闭先于对应 Session。
- 状态：压缩配置、当前任务、来源日志版本、候选结果、取消与提交关联；每 Session 同时最多一个压缩提交过程。
- 请求：解析配置、开始压缩、取消、查询进度、关闭。
- 实现：请求 Session 快照 → 执行选择/摘要任务 → 请求 Session 校验来源版本并提交 → 报告最终结果。
  算法与模型 adapter 保持普通对象，日志提交权不转移。
- 失败/关闭：版本冲突明确结束本次提交或重新取快照发起新任务，禁止拿旧摘要覆盖新日志。
  正常关闭等待已接纳任务，显式取消要收齐摘要任务与已发提交结果。

### QueryActor

- 身份与创建：服务器级查询入口 Grain；单次请求及游标按查询 ID 隔离，不为每次简单查询创建永久 Grain。
- 状态：查询配置、并发预算、活动查询、快照选择与游标、取消记录。
- 请求：查询 Session/投影、继续分页、取消、释放游标、关闭。
- 实现：明确选择数据来源及版本，异步向 Session/ProjectionActor 请求，返回结果和业务游标，不返回存储句柄。
  不需要统一查询协调的简单快照读取仍可直接请求源 Actor，不强制重复转发。
- 失败/关闭：游标失效明确报错；取消下游并释放预算；关闭拒绝新查询并结算既有请求。表达式/过滤是普通函数。

### ProjectionActor

- 身份与创建：每种独立投影及其分区一个稳定身份，Query/服务器按需要启用；具体分区由投影业务定义。
- 状态：源日志位置、已应用序号、checkpoint、重建进度与失败状态。
- 请求：读取投影快照、推进消费、重建、查询进度、关闭；通知只唤醒补读，不是唯一数据源。
- 实现：从 Session 日志补读 → 按序应用 → 持久化投影及对应进度后公布可查询版本。
  同一事件重放不重复产生效果；存储不能原子更新投影和进度时，应用必须具备幂等依据。
- 失败/关闭：失败不越过未应用事件、不回滚源日志；查询显示数据版本，不能伪装已经追平。
  关闭完成当前更新并保存进度；重建与增量切换由本 Actor 串行协调。

## 8. InteractionActor、WorkspaceActor 与 MCPConnectionActor

### InteractionActor

- 身份与创建：每 Agent 一个，承接问答与审批等待状态；两种请求使用独立类型，保留既有外部 schema。
- 状态：待回答/审批请求、有效回答规则、取消和关闭记录。
- 请求：创建交互、提交回答、取消、查询待处理交互、关闭。
- 实现：回答经验证后关联回原 AgentLoop 操作；重连查询恢复待回答列表，不因交互而启动下一条用户业务。
- 失败/关闭：重复回答不重复推进执行；取消后迟到回答拒绝；Agent 排空可能等待有效回答，强制中止走显式取消流程。

### WorkspaceActor

- 身份与创建：按工作区业务身份，由工作区能力初始化；多个 Agent 是否共享同一工作区由配置决定。
- 状态：工作区配置/版本、绑定关系、资源准备与释放状态。
- 请求：解析工作区配置、绑定/解绑 Agent、请求操作所需的工作区约束、关闭。
- 实现：返回路径/约束等业务值，不返回打开的资源句柄；每个实际文件/进程 adapter 仍在效果处检查权限。
- 失败/关闭：准备失败不公布可用；最后绑定及活动操作结算后释放共享资源，不因单个 Agent 关闭误伤其他绑定。

### MCPConnectionActor

- 身份与创建：首期按 AgentID + MCP server 配置标识，由 Tools 能力初始化；首期不跨 Agent 共享连接。
- 状态：连接状态、连接代次、远端请求关联、工具发现版本、重连与取消进度。
- 请求：连接、发现工具、执行远端调用、取消、查询状态、关闭。
- 实现：传输 task 收到结果后回本 Actor 结算；工具目录变化交给 Tool Runtime 排队更新，连接层不直接发布模型工具集。
- 失败/关闭：断连立即使对应调用失败/未知，重连不能自动重放工具副作用；取消请求、收齐传输任务后关闭。
  既有 MCP swap 冲突语义仍需兼容评审，不能因为本版确定了 owner 就假称已解决。

## 9. NotificationBridge 与 TopicActor

NotificationBridge 是普通 Actor，按消费者订阅建立，由消费者初始化/关闭流程管理。它保存订阅确认、
有限缓冲、通知版本及投递状态，接受订阅、通知、解除订阅和关闭消息。只将通知经 Runtime 送给消费者，
不修改业务快照；投递失败使消费者进入补读流程。TopicActor 是 GoAkt 提供的 PubSub 实现，不新建同名业务 owner。

## 10. 实施与测试要求

上述 owner 在所属能力包内实现，不机械新增 internal/*runtime 目录。每个 owner 的测试至少覆盖：
初始化失败/重试、主要成功路径、取消和迟到消息、关闭失败/重试、重新激活、资源释放及消息权限。
跨 owner 测试还须覆盖 Runtime 逻辑寻址、配置获取与初始化分离、稳定 ToolActor 更新、压缩提交冲突、
投影补读、查询取消和凭据更新失败。现有 19 项实验没有证明这些完整生产协议已实现。
